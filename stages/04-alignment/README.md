# 第四阶段：从“会续写”到“按要求完成任务”

[回到总览](../../README.md) · 上一阶段：[数据与规模](../03-data-scaling/README.md) · 下一阶段：[智能体](../05-agents/README.md)

**状态：尚未实现。第一阶段目前反复输出常见词的模型，还不能当作本阶段的合格起点。**

## 1. 任务是什么，有什么意义

一个会续写文章的模型，不一定会按照用户要求答题，更不一定能发现自己做错了。这一阶段要在**相同起始模型**上比较三种学习方式：

```text
给它示范正确答案 → SFT
告诉它两份答案哪个更好 → DPO
让它做题，程序检查对错后给反馈 → RLVR
```

目标不是宣布某种方法最好，而是用相同任务和公平预算，说明每种信号能改善什么、代价是什么、什么时候失效。

## 2. 名词是什么意思

| 名词 | 通俗解释 |
| --- | --- |
| 基座模型 | 已经过一般文本预训练、尚未针对当前任务继续训练的起点模型。 |
| 后训练 | 在预训练之后，用示范、偏好或奖励等信号继续调整行为。 |
| 对齐 | 让行为更符合明确要求；这里要具体到可测任务，不能只用“更听话”描述。 |
| SFT，监督微调 | 给“问题 + 参考回答”，训练模型提高这些回答的概率。 |
| DPO，直接偏好优化 | 给同一个问题的一对答案，标出较好与较差，训练模型相对更偏好较好答案。不是简单只背较好答案。 |
| RL，强化学习 | 模型采取行动产生结果，根据奖励信号调整策略。 |
| RLVR，可验证奖励的强化学习 | 奖励来自可检查的结果，例如算术答案正确或程序通过测试，而不是只凭另一模型打分。 |
| Verifier，验证器 | 按明确定义检查结果的程序；验证器有漏洞时也可能奖励错误行为。 |
| Reward Hacking，奖励投机 | 利用评分规则漏洞拿高分，却没有真正完成任务。 |
| 公平对照 | 固定起点、任务和评估方式，记录数据与计算开销，不让起点差异冒充算法收益。 |

## 3. 先做什么，后做什么

1. **冻结起点和考题。** 保存同一模型与分词规则，准备不进入训练的题集；先测未做后训练时的能力。
2. **准备三类训练信号。** SFT 用参考回答，DPO 用偏好对，RLVR 用可执行的对错检查；交代数据来源和错误处理。
3. **做 SFT 基线。** 先检查模型是否能学习任务格式和示范，避免把“不会输出规定格式”混同于“不会推理”。
4. **训练 DPO 与 RLVR 分支。** 明确从同一基座出发，还是从同一份 SFT 权重出发。如果只有部分分支先做了 SFT，就要把这份额外成本算进去，不能称完全相同起点。
5. **统一评估。** 在固定未见题上比较正确率、输出合规率和资源消耗；检查奖励高但实际答错的例子。

## 4. 为什么用这个方案

三种方法的区别首先在于**学习信号**，不是名字。示范适合告诉模型怎么做，偏好适合比较候选答案，可验证奖励适合答案能被外部程序检查的任务。数据难度和评分规则不同，也会改变结果。

因此先固定可比较条件，再讨论哪种方法更好。只比较各自的训练损失或奖励没有意义：三种方法的目标不同，数字不在同一个尺度上。

## 5. 效果怎样，怎样才算做完

**现在没有 SFT、DPO、RLVR 的训练或对照结果。**

完成时本篇应放一张同任务对照表：各分支实际起点、训练数据、资源开销、未见题正确率与失败样例。提高得分但没有改善真实任务的情况必须披露；不能用训练奖励上升代替任务成功。

第五阶段会把这种“按要求行动并接受反馈”的能力，放进需要多步操作的环境；并不是训练出能聊天的回答就自动具备智能体能力。
