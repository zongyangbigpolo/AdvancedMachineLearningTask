# 第五阶段：让模型行动、检查，并连续完成任务

[回到总览](../../README.md) · 上一阶段：[任务与对齐训练](../04-alignment/README.md)

**状态：尚未实现。下面是任务说明，不是已经搭好的智能体系统。**

## 1. 任务是什么，有什么意义

前面的模型主要输出一段答案。这一阶段让它完成**需要多次行动、每次根据结果继续决策的任务**，并由外部规则验证是否真的成功。

例如设计一个受控文件任务：“找到某条记录，修改指定字段，保存，再核对结果。”模型不能只回复“我改好了”，必须真的执行允许的操作，且最终状态通过检查。

要交付一个可验证环境、一套模型与工具交互的运行框架，以及长程任务训练和效果记录。可以额外比较“自我检查后再改进”的循环有没有帮助。

## 2. 名词是什么意思

| 名词 | 通俗解释 |
| --- | --- |
| Agent，智能体 | 在循环中观察状态、决定动作、调用工具，再根据结果继续行动的系统；不只是一次回答。 |
| 环境 | 模型行动会影响的世界，例如一个受控文件目录或模拟任务状态。 |
| 工具 | 模型可以请求的操作，例如查记录、修改字段；不是允许它随意执行所有系统命令。 |
| Harness，运行框架 | 连接模型、环境和工具的程序，负责传递输入输出、执行动作、限制预算、保存日志。 |
| Observation / Action | 模型看见的当前信息 / 请求执行的动作。 |
| Trajectory，轨迹 | 一次任务从开始到结束的观察、动作、反馈记录，用于复查和训练。 |
| Verifier，验证器 | 根据实际环境状态判断任务成功与否，不靠模型口头宣布完成。 |
| 长程任务 | 需要多次相互依赖的行动；早期错误可能到后面才显现。 |
| Self-judge，自我评估 | 模型评价自己的中间结果并尝试修改。这是建议性反馈，不是客观成功证明。 |
| Loop，循环 | 重复“观察 → 行动 → 反馈 → 再决定”，到成功、失败或预算耗尽时停止。 |

## 3. 先做什么，后做什么

1. **先定义可检查的任务。** 写清初始状态、允许动作、成功条件和失败条件；任务要能重置，才能公平比较不同模型。
2. **实现运行框架。** 模型提出动作，框架校验参数和权限后执行，再把真实结果反馈给模型；设置步数、时间和资源上限。
3. **先跑简单短任务。** 用规则程序或已有模型建立起点结果，确认环境与验证器没有把假成功判成成功。
4. **记录轨迹并训练。** 用经过验证的示范或环境奖励改进模型，逐步增加动作链长度，不一开始就把所有问题混在长任务里。
5. **加入自我检查对照。** 比较有无 self-judge 的成功率、行动次数和成本；允许它提出修改，但最终仍由外部验证器验收。

## 4. 为什么用这个方案

先有环境和可靠成功标准，再训练，才能知道模型到底改善了什么。否则系统可能很会解释、很会说“完成”，但没有改变任何实际状态。

先短后长，便于区分是工具格式不对、单步判断不对，还是多步规划失败。自我检查可能纠错，也可能反复强化同一个错误，所以必须做对照，而不是默认多循环几次就更聪明。

工具执行采用隔离目录和最小权限，避免把训练试错直接作用到用户的真实文件或外部系统。

## 5. 效果怎样，怎样才算做完

**目前没有任务环境、Harness、长程训练或 self-judge 对照结果。**

完成时本篇应展示一条可重放的实际任务轨迹、外部验证结果，以及不同任务长度下的成功率、平均行动次数和成本。测试任务不能直接复用训练答案；模型自评“正确”的比例不作为成功率。

最后把五个阶段的真实结果连成英文报告和现场 Demo：解释问题是什么、为什么值得做、采用什么方法、结果如何，以及哪些部分尚未解决。报告格式不能替代实验本身。
