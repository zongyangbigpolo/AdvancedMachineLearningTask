## 1. 任务是什么，有什么意义

这一阶段有两个相互关联的问题：**原始数据能不能变成值得训练的材料？有限算力应该分给多大的模型、多少数据？**

要交一条有记录的数据清洗流程，以及一组小规模真实训练实验。然后用这些实验预测一个更大设置的损失，再实际检验预测，而不是只画一条看起来漂亮的曲线。

## 2. 名词是什么意思

| 名词 | 通俗解释 |
| --- | --- |
| Dump，原始转储 | 一大批未经本项目清理的原始数据，例如网页抓取存档；里面可能有正文、菜单、广告和乱码。 |
| 语料 | 准备用来训练或评估的文本集合。 |
| 清洗 | 解析正文、处理编码、排除无效或低质量文本，并记录规则和影响。 |
| 精确 / 近似去重 | 去掉完全相同的文本，以及只改了少量内容的重复文本。 |
| 数据泄漏 | 验证题或其近似副本进入训练，造成模型看似会做新题，实际可能只是见过答案。 |
| 数据卡 | 说明数据来源、授权、语言、加工规则、规模和局限的文档。 |
| Scaling Law，规模法则 | 用实验近似描述模型大小、训练数据量、计算量和损失之间的关系；不是对任何任务都必然成立的定律。 |
| 拟合 | 找一组公式参数，使公式尽量贴近已测结果。 |
| 外推 | 用拟合结果预测已经测过的范围之外的设置，风险比范围内估计更大。 |
| 留出检验 | 故意不把一个实验点用于拟合，预测它后再和真实结果比较。 |
| 消融 / 对照 | 尽量只改变一个因素，检查效果变化是否来自它。 |

## 3. 先做什么，后做什么

1. **确认来源与使用权。** 记录下载位置、版本、授权和文件摘要；摘要是检测文件内容是否变化的标识。
2. **解析并清洗。** 从原始记录提取正文，处理坏编码、空文本、语言和质量问题；每步记录剩多少、为什么删除。
3. **去重并划分训练与验证。** 可以先按来源规划划分；无论先后，最后必须检查跨集合重复，防止验证答案混入训练。
4. **只用训练数据学习分词规则。** 固定分词器与验证集，再把数据转成模型可读的编号；否则不同实验的损失可能不可直接比较。
5. **跑多个规模的训练。** 用不同参数量和训练 token 预算，明确哪些条件保持不变；有条件时用多个随机种子估计波动。
6. **拟合并验证预测。** 用一部分实验点建立关系，预测留出的更大实验，再报告实际差距与适用范围。

## 4. 为什么用这个方案

先处理数据质量，再讨论增大模型，否则可能只是在用更多算力学习重复、错误或泄漏的内容。固定验证方式，让不同实验测的是同一件事。

先跑小实验再预测大实验，可以降低盲目扩大的成本，但不是“大模型一定按公式变好”的保证。保持数据量相同与保持计算量相同是两种不同实验，不能把其中一种直接解释为所有条件下的规模法则。

## 5. 效果怎样，怎样才算做完

**目前没有原始 dump 清洗结果，也没有本仓库的规模法则拟合。** 第一阶段 100 步的损失下降不能替代这些证据。

完成时本篇应给出：每步清洗前后文档数、删除原因、重复率与样本检查，数据卡，以及各模型的参数量、训练 token、计算预算、验证损失、预测误差。外推失败也应记录，不能只留下最贴近公式的点。

这一阶段的结果会反过来改进第一阶段的正式预训练：选择更适合的数据与规模，再把得到的合格模型交给第四阶段。它不是只做一次报告便永远不再调整的步骤。
